# HoyaTradingSW 보안 점검 매뉴얼

## 범위와 판정 기준

웹 저장소와 Windows 데스크톱 저장소의 기준 커밋, 로컬 실행 상태, 패키지 버전과 점검 시각을 기록한다. OWASP ASVS 5.0과 Electron 보안 체크리스트를 참고한다. 각 항목은 통과, 발견, 해당 없음, 검증 보류로 기록하며 코드 근거와 실행 결과를 구분한다.

실행 검증은 이 PC의 프로젝트 서비스와 격리된 테스트 설정에서 수행한다. 실거래, 실제 주문, 외부 대상 점검, 자격 증명 확인용 출력, 운영 데이터 변경 없이 진행한다. 보고서에는 시크릿 값·요청 토큰을 적지 않는다.

## Windows에서 다시 점검하기

1. 각 저장소에서 `git status --short --branch`, `git rev-parse HEAD`, `node -v`, `.venv\Scripts\python.exe -V`를 기록한다. 기본 브랜치가 작업 브랜치와 다르면 별도 기준으로 기록한다.
2. 각 프런트엔드와 데스크톱 저장소 루트의 잠금 파일에 `npm audit --package-lock-only --json`을 실행한다. 잠금 파일이 없는 과거 브랜치를 비교할 때는 임시 경로에 한해 설치 스크립트 없이 의존성을 해석하고 결과에 그 사실을 기록한다.
3. 검사 도구는 별도 환경에 설치한다. `pip-audit -r requirements.txt`와 `pip-audit -r research/requirements.txt`로 선언 의존성을 검사한다. 실제 설치본은 `pip freeze --all`로 목록을 만든 후 `pip-audit --disable-pip --no-deps -r <snapshot>`으로 따로 확인한다. `pip check`로 설치 의존성 충돌을 점검한다. 권고 번호의 별칭은 동일한 문제로 볼 수 있으므로 도구가 출력한 총건수와 패키지 수를 구분한다.
4. Gitleaks의 `git --redact=100 --log-opts=--all`로 로컬 Git 참조를 검사한다. 탐지한 값은 출력하지 않고 규칙과 파일 단위로 분류한다. Python은 Bandit으로 추적된 소스를 점검하고, SQL·해시·외부 호출 경고는 해당 데이터의 출처와 흐름을 읽어 검토한다.
5. `netstat -ano -p tcp`로 프로젝트 포트의 리스너를 확인한다. 로컬 웹 페이지와 `/healthz`의 정상 응답 헤더를 확인하고, 브라우저가 사용할 출처의 CORS 정책을 점검한다. Electron에서는 별도 포트와 임시 실행 프로필을 사용하는 `npm run smoke`로 무토큰 요청 거부와 게이트웨이 허용 목록을 검증한다.
6. 운영/보안·실거래 제어, 원장 복구, 데스크톱 게이트웨이의 기존 테스트를 실행한다. 앱 버전의 보안 권고와 방화벽, TLS, 인증 실패 시 동작, 권한 테스트 범위를 보고서에 기록한다.
