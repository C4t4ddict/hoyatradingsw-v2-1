# 차트 중심 대시보드 설계

기준은 TradingView의 상단 종목 도구 모음, 중앙 캔들, 오른쪽 정보, 하단 탭이다. Hoya의 짙은 남색과 초록 강조색, 한국어 탐색 구조를 사용한다.

| ID | 요구사항 |
| --- | --- |
| D1 | 상단에 모의투자 상태, 수집 상태·최근 성공, 일일 손실 한도, 가상 자산·성과를 표시한다. 결측값과 실제 0을 구분한다. |
| D2 | BTC·ETH·SOL의 확정 4시간봉과 거래량을 표시한다. 종목 및 1주·1개월·3개월 전환, 마우스와 키보드로 봉 조회, KST 시각 및 가격 축을 제공한다. |
| D3 | 오른쪽에 종합 방향, ML 정책 활성 여부·표본 수, 상승/하락 점수, 뉴스 근거를 표시한다. 뉴스는 번역 제목과 원문 링크를 제공한다. |
| D4 | 하단에 신호 결과, 뉴스, 수집 로그 탭을 제공한다. 신호는 결과 대기와 정산을 구분하고 수익률은 비용 차감 후 값을 사용한다. |

`GET /api/runtime/candles?symbol=BTC%2FUSDT`는 기존 SQLite 캐시에서 허용된 종목의 확정 4시간봉을 최대 540개 읽는다. 응답은 종목, 간격, UTC 밀리초 OHLCV 배열, 지연 상태를 담는다. 차트는 Canvas로 그리며 시간 간격을 보존해 결측 구간을 빈 공간으로 표시한다.

뉴스 표식은 관측 시각의 구간, 신호 표식은 해당 종목과 실제 관측 시각의 구간에만 연결한다. 아직 확정되지 않은 시간대의 이벤트는 하단 내역에서 볼 수 있다. 뉴스는 전체 시장 이벤트로 표시하고 가격 변동의 원인으로 해석하지 않는다. 수집 오류와 빈 데이터는 각각 명시한다.

검증 범위는 캐시 조회 경계와 잘못된 종목, 차트 범위·이벤트 시각 매핑, 로컬 데스크톱에서 종목·기간·탭 전환이다. 저장소의 일반 Next.js 빌드와 CI가 통과하면 develop에 merge commit으로 병합한다.
