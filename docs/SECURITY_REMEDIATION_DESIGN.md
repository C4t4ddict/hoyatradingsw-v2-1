# 웹·데스크톱 보안 개선 설계

## 요구사항

- SEC-1. Next.js와 Python 런타임 의존성을 패치하고 잠금/감사 결과와 호환성을 검증한다. 웹 기본 브랜치의 배포 기준도 확인한다.
- SEC-2. 기본 웹 런처는 루프백에 바인딩한다. 웹 API는 허용한 출처만 CORS로 허용하며 데스크톱은 기존 루프백 게이트웨이를 사용한다.
- SEC-3. 웹 변경 API에 설정 토큰을 적용한다. 전략 승인자는 서버에서 확인된 운영자 주체로 기록한다. 레거시 계정 조회와 변경은 토큰 미설정 시 거부한다. 데스크톱 토큰과 허용 목록으로 기존 모의투자가 동작하도록 한다.
- SEC-4. 웹과 데스크톱 응답에 렌더링과 호환되는 보안 헤더를 추가한다. 공개 시세와 뉴스, 백테스트에 사용하는 HTTPS 요청은 백엔드에서 계속 처리한다.
- SEC-5. 외부 피드의 목적지, 리다이렉트, 응답 크기와 XML 파싱을 제한한다. 모델 파일은 신뢰된 경로와 파일 무결성을 확인할 수 있도록 한다.
- SEC-6. CI 의존성을 검증 가능한 버전으로 고정하고 안전한 Windows 배포에 필요한 서명과 검증 절차를 명시한다. 실제 서명과 운영 TLS 확인에는 사용자 소유 인증서 또는 배포 정보가 필요하다.

## 검증

- 일반 빌드, 각 저장소 변경 범위 회귀 테스트, npm 및 Python 권고 재검사, Electron 테스트를 실행한다.
- 정상 공개 데이터 요청, 설정 토큰의 유효·무효 입력과 루프백 응답을 확인한다. 실제 주문과 거래소 비공개 API는 호출하지 않는다.
